# D-04 · 会话 debug 审计

完成本章后：能打开审计开关，在发送/再生后查看某轮的提示词、组装命中与性能数据；并知道「预览」与磁盘上的审计文件是什么关系。

## 审计是干什么的

**会话 debug 审计**在每次**发送**或**再生**成功落盘后，由服务端把本轮相关信息写入该对话的 `chat-audit.json`，便于排查：

- 实际发给模型的**提示词**（messages）
- **资料库 / 记忆 / 知识库**等组装命中
- **群聊选人**过程（若适用）
- **出站 API 调用**记录
- **性能**分段耗时（组装、上游、落盘等）

适合：回复不符合预期、想确认资料库有没有注入、或调试群聊选人时。日常纯聊天可以不开。

---

## 第一步：全局开启

1. 顶栏 **齿轮** → **设置**。
2. 左侧 **调试**。
3. 打开 **「启用会话 debug 审计」**。
4. （可选）调整 **「最多保留审计条数」**（1～200）。进入某场对话时，会同步到该对话的 `auditDebug`（开关 + 上限）。

关闭开关后：**不再写入**新条目；此前已落盘的条目仍保留在数据目录中，但助手消息旁的 **「审计」** 按钮仅在开关**开启**时显示。

---

## 第二步：产生一条审计

1. 打开任意对话。
2. **发送**一条消息，或对某条助手回复 **再生**。
3. 落盘成功后，该轮会写入（或更新）审计记录。

若助手旁没有 **「审计」** 按钮，回到 **设置 → 调试** 确认开关已开，并刷新页面。

---

## 第三步：查看某轮审计

在**助手消息**工具栏点击 **「审计」**（文档图标），打开 **「本轮 debug 审计」** 对话框。

顶部显示轮次、保存时间、`turnId`、块文件等元信息。下方 Tab：

| Tab | 内容 |
|-----|------|
| **提示词** | 发给模型的 message 列表；可 **复制提示词** / **复制原始 JSON** |
| **组装命中** | token 估算、预算裁切、插件注入预留、记忆/资料库/知识库/历史命中等 |
| **群聊** | 本段/下段选人方式、掷骰表、speaker 等（仅群聊轮次有数据） |
| **出站调用** | 上游 API 调用摘要 |
| **性能** | 组装、记忆召回、资料库、**出站/落盘正则**、上游 TTFB/首 token/生成 TPS、落盘等耗时 |

某 Tab 显示「无 … 数据」时，通常表示该轮未产生对应字段，或未开启审计时发送的较旧轮次。

核对「出站正则有没有改坏发给模型的内容」时：看 **提示词** Tab（已是出站处理后的结果），规则本身见 [B-06 · 正则替换入门](B-06-regex-rules.md)。

---

## 发送前预览（可选）

输入框工具栏 **「预览」** 可在**不发送**的情况下，按当前输入与对话设置在服务端组装 prompt（与点击发送时的组装一致，**不含插件 hook**）。

同样需要 **设置 → 调试** 里已开启 **「启用会话 debug 审计」**。失败时会提示去调试页开启。

---

## 数据落在哪

审计条目写在当前用户数据目录下该对话相关路径的 **`chat-audit.json`**（与 `chats/` 同属该用户 `data/{userId}/`）。条目过多时按 **最多保留审计条数** 淘汰最旧记录。

备份 `data/` 时会一并包含；勿在多台机器同时写同一数据目录。

---

- [ ] 已在 **设置 → 调试** 打开 **启用会话 debug 审计**。
- [ ] 发送或再生后，助手消息旁能点 **审计**，并能在 **提示词** / **组装命中** Tab 看到内容。
- [ ] 知道 **预览** 也依赖同一开关。
